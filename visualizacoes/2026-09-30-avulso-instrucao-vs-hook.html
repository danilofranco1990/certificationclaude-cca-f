Pedido ou portão

A regra “nunca edite arquivos em infra/prod/” escrita como instrução e como hook, na mesma sessão longa. Você configura a proteção, faz o papel do modelo no turno 41 e observa o arquivo em disco.

Esta simulação não faz chamadas reais. Nenhum modelo, hook ou arquivo é executado. Tudo é calculado no navegador a partir das suas escolhas.

      Quanto vale “quase sempre”
      
  
      O material diz que o modelo atende a instrução quase sempre, e que quase é o que uma política de segurança não aceita material. Ajuste a taxa e o número de oportunidades. A taxa é hipotética: a doc não publica taxa de obediência, e a conta supõe tentativas independentes, todas com Edit ou Write simulação.

      HookHandler configurado em settings.json que o Claude Code executa automaticamente num ponto fixo do ciclo de vida. Instrução em prompt é probabilística; hook é determinístico.material
      
    
      CLAUDE.md é contexto“Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead.”doc oficial
      
    
      Compaction“Project-root CLAUDE.md survives compaction.” Some o que foi dito só na conversa, um CLAUDE.md aninhado que ainda não recarregou ou uma regra com paths: que ainda não casou com arquivo.doc oficial
      
    
      Exit 0“Exit code 0 with no output means the hook has no decision to report… The hook can deny the call, but staying silent doesn't approve it.”doc oficial
      
    
      Exit 2 em PreToolUse“Blocks the tool call.” Um JSON com allow não desfaz o exit 2. “Claude sees the stderr message as the denial reason.”doc oficial
      
    
      Outros códigosNão bloqueiam. O transcript mostra o aviso com “Failed with non-blocking status code:”. Um caminho de script errado cai no mesmo aviso: “a mistyped path in settings.json leaves the gate silently disabled.”doc oficial
      
    
      permissionDecisionallow, deny, ask, defer. Entre hooks, vence deny > defer > ask > allow. Um allow não passa por cima das regras de deny do settings.doc oficial
      
    
      Modos de permissão“A hook that returns permissionDecision: "deny" blocks the tool even in bypassPermissions mode or with --dangerously-skip-permissions.”doc oficial
      
    
      PostToolUseExit 2: “Shows stderr to Claude; the tool already ran.” “PostToolUse hooks can't undo actions since the tool has already executed.”doc oficial
      
    
      PostToolUseFailure“Runs when a tool that started executing fails.” Uma chamada barrada antes da execução não o dispara.doc oficial
      
    
      MatcherSó letras, dígitos, _, -, espaço, vírgula e |: lista de nomes exatos. Qualquer outro caractere: regex JavaScript sem âncora. “Matchers are case-sensitive.”doc oficial
      
    
      Onde configurar.claude/settings.json é do projeto e pode ser commitado: é o lugar de uma regra da equipe. ~/.claude/settings.json fica só na sua máquina.material doc oficial
      
    
      Desfazer depoisEdições de arquivo têm checkpoint: Esc duas vezes volta atrás. Ações em sistemas remotos não têm. Isso é alguém revertendo depois, não o hook impedindo.doc oficial
      
  
      
  
      

  
      
    
      
      
      Erros de interpretação frequentes
      
      
        
        
      • “Regra em negrito, no topo, resolve.” Continua instrução e continua probabilística material.
        • 
        
      • “Um PostToolUse que registra tudo é um gate.” Ele detecta com o dano feito. Para impedir, só PreToolUse material.
        • 
        
      • “Exit 1 bloqueia, é o código de erro.” Só o 2 bloqueia. Exit 1 é erro não bloqueante material.
        • 
        
      • “Matcher Edit cobre qualquer escrita.” Write fica de fora material, e Bash também doc oficial.
        • 
        
      • “Exit 0 aprova a chamada.” Não aprova: ela segue o fluxo normal de permissão doc oficial.
        • 
        
      • “A compaction apaga o CLAUDE.md.” O da raiz é reinjetado do disco. Some o que foi dito só na conversa doc oficial. A regra do CLAUDE.md da raiz ainda pode perder para outra instrução material.
        • 
        
      • “Determinístico quer dizer cobertura total.” O hook é determinístico dentro do matcher e do que o script inspeciona. Um script que lê file_path não vê um caminho escrito dentro de um comando.

      Pedido e portão: o mapeamento
      
      
      
        
      No títuloNo Claude Code
      
        
      PedidoA regra no CLAUDE.md: o modelo pode atender ou não.
      
        
      PortãoO handler em PreToolUse: roda em toda chamada que o matcher seleciona.
      
        
      TrancaExit 2 ou permissionDecision: "deny".
      
        
      CâmeraPostToolUse: vê e registra depois que a ação passou.
      
        
      Porta lateralUma ferramenta fora do matcher, como Bash.
      
      
      
      
      Onde a analogia deixa de valer. Um portão barra quem passa por ele; o hook só avalia o que o script sabe ler. O hook pode reescrever o pedido antes de executar, com updatedInput, ou pedir confirmação, com ask, e portão não faz isso. E quem é barrado recebe o motivo por escrito e pode tentar outro caminho.
