Blocos doc oficial

  • tool_use (escrito pelo modelo, turno assistant): id, name, input conforme o input_schema.
  • tool_result (escrito pela aplicação, turno user): tool_use_id (obrigatório), content (opcional: string ou blocos text/image/document), is_error (opcional, true em falha).

Regras de forma doc oficial

  • A mensagem user com os tool_result vem imediatamente após a mensagem assistant com os tool_use. Nada entre elas.
  • Os tool_result vêm primeiro no content; texto só depois. Texto antes → erro 400.
  • Um tool_result para cada tool_use, todos na mesma mensagem user. Se não executou uma chamada, ainda assim devolva is_error: true com explicação.
  • tool_use sem tool_result logo depois → 400: "tool_use ids were found without tool_result blocks immediately after".
  • Paralelismo é o padrão; tool_choice: {"type":"auto","disable_parallel_tool_use":true} limita a no máximo um tool_use por resposta. Devolver resultados em mensagens user separadas "ensina" o modelo a parar de paralelizar.
  • Reação a is_error: Claude "tipicamente reconhece o erro e tenta outra abordagem ou pede esclarecimento" — comportamento típico, não garantia.

Erros de interpretação frequentes

  • "O modelo executa a ferramenta." Não. O modelo escreve o pedido (tool_use) e para. Quem executa é a aplicação — sem caminho físico nem permissão para o modelo tocar o banco. material
  • "O tool_result vai num turno assistant ou num papel tool." Vai em role: "user": tudo que chega ao modelo vem de fora. Não existe papel tool nesta API. doc oficial
  • "Gravo só o texto da resposta no histórico." Perde os blocos tool_use; o tool_use_id fica órfão e a próxima requisição é rejeitada. Grave response.content inteiro. material
  • "Um tool_result por mensagem." Todos na mesma mensagem user, primeiro no content. doc oficial
  • "Se a ferramenta falhou, não devolvo nada / invento um resultado." Devolva is_error: true com a mensagem do erro; silêncio deixa o turno suspenso, invenção engana o modelo. material
  • "A aplicação escolhe quantos tool_use o modelo emite." Quem produz os blocos é o modelo. A aplicação pode no máximo limitar com disable_parallel_tool_use. doc oficial
  • "Mostro o texto que veio com o tool_use como resposta final." O turno está suspenso; o usuário vê "vou consultar…" e nada acontece, para sempre. material
  • "Depois de um erro o modelo sempre tenta de novo." É comportamento típico, não contrato. A continuação depende do modelo, do prompt e do erro. doc oficial
