    Erros de interpretação frequentes

    • “stop_reason é um campo informativo.” É a condição do laço. A linha 5 decide, a cada volta, se o agente continua material.
    • “Quem decide quantas voltas é o meu código.” Quem decide é o modelo, pelo stop_reason de cada resposta. O seu código só consegue pôr um teto material.
    • “Gravar só o texto funciona, testei.” Funciona enquanto não houver tool_use. O erro aparece uma volta depois, na requisição seguinte, e aqui dá para ver isso acontecer simulação.
    • “senão quer dizer end_turn.” O senão pega também max_tokens, refusal e stop_sequence. Sem tratamento, texto cortado ou vazio vira “resposta final” doc oficial.
    • “Recusa é um erro HTTP.” É um 200 com stop_reason: "refusal" doc oficial.
    • “Negar uma ferramenta é não responder.” Todo tool_use recebe um tool_result. O negado vai com is_error: true e uma explicação doc oficial.
    • “O Tool Runner elimina o laço.” Ele roda o mesmo laço, dentro do seu processo. Para aprovação, log próprio ou execução condicional, a doc indica o loop manual doc oficial.
